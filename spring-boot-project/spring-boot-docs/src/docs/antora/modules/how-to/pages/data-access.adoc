[[howto.data-access]]
= 数据访问

Spring Boot 提供了多个用于数据源操作的 starter。
本节解答与数据源相关的问题。



[[howto.data-access.configure-custom-datasource]]
== 配置自定义 DataSource

要配置你自己的 javadoc:javax.sql.DataSource[]，只需在配置类中定义一个该类型的 javadoc:org.springframework.context.annotation.Bean[format=annotation]。
Spring Boot 会在任何需要的地方（包括数据库初始化）复用你的 javadoc:javax.sql.DataSource[]。
如果需要将部分设置外部化，可以将 javadoc:javax.sql.DataSource[] 绑定到环境（参见 xref:reference:features/external-config.adoc#features.external-config.typesafe-configuration-properties.third-party-configuration[]）。

以下示例展示了如何在 bean 中定义数据源：

include-code::custom/MyDataSourceConfiguration[]

以下示例展示了如何通过属性设置数据源：

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:h2:mem:mydb"
    username: "sa"
    pool-size: 30
----

假设 `SomeDataSource` 拥有 URL、用户名和连接池大小等常规 JavaBean 属性，这些设置会在 javadoc:javax.sql.DataSource[] 被其他组件使用前自动绑定。

Spring Boot 还提供了一个名为 javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] 的实用构建器类，可用于创建标准数据源（如果在 classpath 上）。
该构建器会根据 classpath 上可用内容自动检测使用哪种数据源，并根据 JDBC URL 自动检测驱动。

include-code::builder/MyDataSourceConfiguration[]

要运行带有该 javadoc:javax.sql.DataSource[] 的应用，只需提供连接信息。
也可以提供特定于连接池的设置。
具体细节请参考运行时所用实现。

以下示例展示了如何通过属性定义 JDBC 数据源：

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
----

但由于方法返回类型为 javadoc:javax.sql.DataSource[]，实际连接池类型被隐藏，因此不会为你的自定义 javadoc:javax.sql.DataSource[] 生成配置属性元数据，IDE 也无法自动补全。
为解决此问题，可使用构建器的 `type(Class)` 方法指定要构建的 javadoc:javax.sql.DataSource[] 类型，并更新方法返回类型。
例如，以下展示了如何用 javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] 创建 javadoc:com.zaxxer.hikari.HikariDataSource[]：

include-code::simple/MyDataSourceConfiguration[]

但这种基础配置并不适用于 Hikari，因为 Hikari 没有 `url` 属性，而是 `jdbc-url`，因此你必须将配置改写如下：

[configprops%novalidate,yaml]
----
app:
  datasource:
    jdbc-url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    pool-size: 30
----

为解决此问题，可使用 javadoc:org.springframework.boot.autoconfigure.jdbc.DataSourceProperties[]，它会帮你处理 `url` 到 `jdbc-url` 的转换。
你可以通过其 `initializeDataSourceBuilder()` 方法，从任意 javadoc:org.springframework.boot.autoconfigure.jdbc.DataSourceProperties[] 对象的状态初始化 javadoc:org.springframework.boot.jdbc.DataSourceBuilder[]。
你可以注入 Spring Boot 自动创建的 javadoc:org.springframework.boot.autoconfigure.jdbc.DataSourceProperties[]，但那样会让你的配置分散在 `+spring.datasource.*+` 和 `+app.datasource.*+`。
为避免此问题，可自定义一个带有自定义配置前缀的 javadoc:org.springframework.boot.autoconfigure.jdbc.DataSourceProperties[]，如下例所示：

include-code::configurable/MyDataSourceConfiguration[]

这种配置等价于 Spring Boot 默认行为，只是连接池类型在代码中指定，相关设置以 `app.datasource.configuration.*` 属性暴露。
javadoc:org.springframework.boot.autoconfigure.jdbc.DataSourceProperties[] 负责 `url` 到 `jdbc-url` 的转换，因此你可以这样配置：

[configprops%novalidate,yaml]
----
app:
  datasource:
    url: "jdbc:mysql://localhost/test"
    username: "dbuser"
    password: "dbpass"
    configuration:
      maximum-pool-size: 30
----

注意，由于自定义配置在代码中指定了 Hikari，`app.datasource.type` 不再生效。

如 xref:reference:data/sql.adoc#data.sql.datasource.connection-pool[] 所述，javadoc:org.springframework.boot.jdbc.DataSourceBuilder[] 支持多种连接池。
如需使用非 Hikari 连接池，将其加入 classpath，使用 `type(Class)` 方法指定连接池类，并更新 javadoc:org.springframework.context.annotation.Bean[format=annotation] 方法返回类型。
这样还能为你选择的连接池生成配置属性元数据。

TIP: Spring Boot 会将 Hikari 专属设置暴露为 `spring.datasource.hikari`。
本例采用更通用的 `configuration` 子命名空间，因为示例不支持多种数据源实现。

更多细节参见 xref:reference:data/sql.adoc#data.sql.datasource[] 及 {code-spring-boot-autoconfigure-src}/jdbc/DataSourceAutoConfiguration.java[`DataSourceAutoConfiguration`] 类。

[[howto.data-access.spring-data-repositories]]
== 使用 Spring Data Repositories

Spring Data 可为多种风格的 javadoc:org.springframework.data.repository.Repository[] 接口自动创建实现。
只要这些 javadoc:org.springframework.data.repository.Repository[] 实现包含在 xref:reference:using/auto-configuration.adoc#using.auto-configuration.packages[自动配置包]（通常是主应用类所在包或其子包，且带有 javadoc:org.springframework.boot.autoconfigure.SpringBootApplication[format=annotation] 或 javadoc:org.springframework.boot.autoconfigure.EnableAutoConfiguration[format=annotation] 注解）中，Spring Boot 会自动处理。

对于大多数应用，只需将合适的 Spring Data 依赖加入 classpath。
JPA 可用 `spring-boot-starter-data-jpa`，MongoDB 可用 `spring-boot-starter-data-mongodb`，其它技术也有相应 starter。
开始时，创建一些用于处理 javadoc:jakarta.persistence.Entity[format=annotation] 对象的 repository 接口即可。

Spring Boot 通过扫描 xref:reference:using/auto-configuration.adoc#using.auto-configuration.packages[自动配置包]确定 javadoc:org.springframework.data.repository.Repository[] 实现的位置。
如需更细致控制，可用 Spring Data 的 `@Enable…Repositories` 注解。

更多 Spring Data 相关内容，参见 {url-spring-data-site}[Spring Data 项目主页]。

[[howto.data-access.jpa-properties]]
== 配置 JPA 属性

Spring Data JPA 已提供部分与厂商无关的配置选项（如 SQL 日志），Spring Boot 还将这些选项及部分 Hibernate 选项暴露为外部配置属性。
部分属性会根据上下文自动检测，无需手动设置。

`spring.jpa.hibernate.ddl-auto` 是一个特殊配置项，因为它会根据运行时条件采用不同的默认值。
如果使用的是嵌入式数据库，且没有像 Liquibase 或 Flyway 这样的 schema 管理器处理 javadoc:javax.sql.DataSource[]，则默认值为 `create-drop`。
在所有其他情况下，默认值为 `none`。

JPA 提供者会自动检测要使用的方言（dialect）。
如果你希望自行指定方言，请设置 configprop:spring.jpa.database-platform[] 属性。

最常用的配置选项如下例所示：

[configprops,yaml]
----
spring:
  jpa:
    hibernate:
      naming:
        physical-strategy: "com.example.MyPhysicalNamingStrategy"
    show-sql: true
----

此外，所有 `+spring.jpa.properties.*+` 下的属性在创建本地 javadoc:jakarta.persistence.EntityManagerFactory[] 时会作为常规 JPA 属性（前缀会被去除）传递。

[WARNING]
====
你需要确保在 `+spring.jpa.properties.*+` 下定义的名称与 JPA 提供者所期望的完全一致。
Spring Boot 不会对这些条目做任何宽松绑定。

例如，如果你想配置 Hibernate 的批量大小，必须使用 `+spring.jpa.properties.hibernate.jdbc.batch_size+`。
如果使用其他形式，如 `batchSize` 或 `batch-size`，Hibernate 将不会应用该设置。
====

TIP: 如果你需要对 Hibernate 属性进行高级自定义，可以注册一个 javadoc:org.springframework.boot.autoconfigure.orm.jpa.HibernatePropertiesCustomizer[] bean，该 bean 会在创建 javadoc:jakarta.persistence.EntityManagerFactory[] 之前被调用。
这会优先生效于自动配置应用的任何内容。



[[howto.data-access.configure-hibernate-naming-strategy]]
== 配置 Hibernate 命名策略

Hibernate 使用 {url-hibernate-userguide}#naming[两种不同的命名策略]，将对象模型中的名称映射到对应的数据库名称。
可以通过设置 `spring.jpa.hibernate.naming.physical-strategy` 和 `spring.jpa.hibernate.naming.implicit-strategy` 属性，分别配置物理和隐式策略实现类的全限定类名。
或者，如果应用上下文中存在 javadoc:org.hibernate.boot.model.naming.ImplicitNamingStrategy[] 或 javadoc:org.hibernate.boot.model.naming.PhysicalNamingStrategy[] bean，Hibernate 会自动使用它们。

默认情况下，Spring Boot 使用 javadoc:org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy[] 配置物理命名策略。
采用该策略时，所有点（.）会被下划线替换，驼峰命名也会被下划线分隔。
此外，默认所有表名都会转为小写。
例如，`TelephoneNumber` 实体会映射为 `telephone_number` 表。
如果你的 schema 需要混合大小写标识符，可以像下面这样自定义 javadoc:org.hibernate.boot.model.naming.CamelCaseToUnderscoresNamingStrategy[] bean：

如果你更倾向于使用 Hibernate 的默认策略，只需设置如下属性：

[configprops,yaml]
----

  jpa:
    hibernate:
      naming:
        physical-strategy: org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
----

[[howto.data-access.use-custom-entity-manager]]
== 使用自定义 EntityManagerFactory

如果你需要完全控制 javadoc:jakarta.persistence.EntityManagerFactory[] 的配置，只需添加一个名为 '`entityManagerFactory`' 的 javadoc:org.springframework.context.annotation.Bean[format=annotation]。
只要存在该类型的 bean，Spring Boot 的自动配置就会关闭自身的 entity manager。

NOTE: 如果你自行创建了 javadoc:org.springframework.orm.jpa.LocalContainerEntityManagerFactoryBean[]，则自动配置期间应用的任何自定义都会失效。
请务必使用自动配置的 javadoc:org.springframework.boot.orm.jpa.EntityManagerFactoryBuilder[]，以保留 JPA 及厂商属性。
如果你依赖 `spring.jpa.*` 属性配置命名策略或 DDL 模式，这一点尤为重要。

[[howto.data-access.use-spring-data-jpa-and-mongo-repositories]]
== 同时使用 Spring Data JPA 与 Mongo 仓库

Spring Data JPA 和 Spring Data Mongo 都可以自动为你创建 javadoc:org.springframework.data.repository.Repository[] 实现。
如果它们同时存在于 classpath 上，可能需要额外配置以告知 Spring Boot 需要创建哪些仓库。
最直接的方式是使用标准的 Spring Data javadoc:org.springframework.data.jpa.repository.config.EnableJpaRepositories[format=annotation] 和 javadoc:org.springframework.data.mongodb.repository.config.EnableMongoRepositories[format=annotation] 注解，并指定 javadoc:org.springframework.data.repository.Repository[] 接口的位置。

你还可以通过配置 `+spring.data.*.repositories.enabled+` 和 `+spring.data.*.repositories.type+` 等标志，在外部配置中切换自动配置的仓库开关。
例如，如果你只想关闭 Mongo 仓库但仍使用自动配置的 javadoc:org.springframework.data.mongodb.core.MongoTemplate[]，这种方式非常有用。

对于其他自动配置的 Spring Data 仓库类型（如 Elasticsearch、Redis 等），同样适用。
只需相应更改注解和配置项名称即可。
